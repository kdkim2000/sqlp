## 3. VI-001 상세: chapter 필드 형식 불일치

### 현황

| 파일 | 현재 chapter 값 | 필요 chapter 값 |
|:---|:---|:---|
| part1_ch1.json | `"1"` | `"part1_ch1"` |
| part1_ch2.json | `"2"` | `"part1_ch2"` |
| part2_ch1.json | `"1"` | `"part2_ch1"` |
| part2_ch2.json | `"2"` | `"part2_ch2"` |
| part2_ch3.json | `"3"` | `"part2_ch3"` |

### 영향 분석

```typescript
// lib/progress.ts getStats() 에서 byChapter 집계 시
for (const q of questions) {
  byChapter[q.chapter].total++  // q.chapter = "1" (현재)
}
// → byChapter는 { "1": {...}, "2": {...}, "3": {...} } 로 집계됨

// 그러나 UI(LearningPath, WeakChapters)에서는
// CHAPTERS 배열의 id("part1_ch1", "part1_ch2" 등)로 접근
// → byChapter["part1_ch1"]은 undefined → 통계 표시 오류
```

### 수정 방법

```python
# 변환 규칙
part1_ch1: chapter "1" → "part1_ch1"
part1_ch2: chapter "2" → "part1_ch2"
part2_ch1: chapter "1" → "part2_ch1"  (파일명으로 구분)
part2_ch2: chapter "2" → "part2_ch2"
part2_ch3: chapter "3" → "part2_ch3"
```

**수정 스크립트 (Node.js)**:
```javascript
// 각 파일별 chapter 값 변환
const mapping = {
  'part1_ch1.json': 'part1_ch1',
  'part1_ch2.json': 'part1_ch2',
  'part2_ch1.json': 'part2_ch1',
  'part2_ch2.json': 'part2_ch2',
  'part2_ch3.json': 'part2_ch3',
}
```

## 4. VI-002 상세: answer 1-based vs 0-based 불일치

### 현황

```json
// 예: p1c1_001 (정답: "추상화, 단순화, 명확화" — 첫 번째 보기)
{
  "options": ["추상화, 단순화, 명확화", "추상화, 정규화, 명확화", ...],
  "answer": 1  // 1-based: 첫 번째 옵션
}

// 예: p1c1_002 (정답: "시스템 관점" — 네 번째 보기)
{
  "options": ["데이터 관점", "프로세스 관점", "상관 관점", "시스템 관점"],
  "answer": 4  // 1-based: 네 번째 옵션
}
```

### 코드 구현 확인 (QuestionCard.tsx)

```typescript
// 키보드 핸들러: 1~4 키 누르면 1~4 전달
const num = parseInt(e.key, 10)
if (num >= 1 && num <= 4) handleSelect(num)

// 정답 비교: 1-based로 비교
const result = optionIndex === question.answer ? 'correct' : 'wrong'
```

**결론**: 데이터(JSON)와 코드(TSX)가 **모두 1-based**로 일관되게 동작 중. 실제 오작동은 없음.

### 권고 사항

**Option A (권장)**: RULES.md의 answer 명세를 **1-based (1~4)** 로 수정
```
- `answer`: 1-based index (1~4 범위)
```

**Option B**: 전체 JSON + 코드를 0-based로 일괄 변환 (대규모 변경, 위험 높음)
